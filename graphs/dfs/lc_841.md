# Keys and Rooms — DFS Solution

## Problem Statement

There are `n` rooms labeled from `0` to `n - 1`. Initially, all rooms except room `0` are locked. Your goal is to visit all the rooms.

Each room contains a list of keys, and each key has a number denoting which room it unlocks. You start in room `0` (which is unlocked).

Given `rooms` — where `rooms[i]` is the list of keys found in room `i` — return `true` if you can visit **all** the rooms, otherwise return `false`.

### Example

```
Input: rooms = [[1],[2],[3],[]]
Output: true
Explanation:
We visit room 0 and pick up key 1.
We then visit room 1 and pick up key 2.
We then visit room 2 and pick up key 3.
We have visited all 4 rooms.
```

## Approach

This is a classic **graph traversal / connectivity** problem.

### Key Insight
Think of each room as a **node** in a graph, and each key found in a room as a **directed edge** to the room it unlocks. The question then becomes:

> Starting from node `0`, can we reach every other node in the graph?

This is answered directly using **DFS (Depth-First Search)**.

### Steps
1. **Represent the graph implicitly**: `rooms[i]` already acts as the adjacency list for node `i` — it lists all rooms directly reachable from room `i`.
2. **Track visited rooms**: Use a `visited` array of size `n`, initialized to `0`, to avoid revisiting rooms and getting stuck in cycles.
3. **DFS from room 0**:
   - Mark the current room as visited.
   - Increment a `count` variable to track how many rooms we've visited so far.
   - For every key (neighboring room) found in the current room, if that room hasn't been visited yet, recursively visit it.
4. **Final check**: After the DFS completes, compare `count` (rooms visited) with `n` (total rooms):
   - If `count == n`, every room was reachable → return `true`.
   - Otherwise, some rooms were unreachable → return `false`.

## Code Walkthrough

```cpp
void dfs(int vertex, vector<int>& visited, vector<vector<int>>& rooms, int &count){
    visited[vertex] = 1;      // Mark current room as visited
    count++;                  // One more room successfully visited

    for(auto node : rooms[vertex]){       // Look at all keys in this room
        if(visited[node] == 0){           // If the room they unlock isn't visited
            dfs(node, visited, rooms, count);  // Recurse into it
        }
    }
}

bool canVisitAllRooms(vector<vector<int>>& rooms) {
    int n = rooms.size();
    int count = 0;
    vector<int> visited(n, 0);

    dfs(0, visited, rooms, count);   // Start DFS from room 0

    return count == n;               // True only if all rooms were visited
}
```

### Why pass `count` by reference?
Since the recursive calls need to accumulate a single running total across all branches of the DFS tree, `count` is passed by reference (`int &count`) so every recursive call updates the *same* variable instead of maintaining separate local copies.

### Why check `visited[node] == 0` before recursing?
This prevents:
- **Infinite loops** in case of cycles (e.g., room 1 has a key to room 0, which already has a key to room 1).
- **Redundant work** — revisiting rooms that have already been explored.

## Complexity Analysis

| Metric | Complexity | Explanation |
|---|---|---|
| **Time Complexity** | `O(V + E)` | `V` = number of rooms (nodes), `E` = total number of keys across all rooms (edges). Each room is visited once, and each key is examined once. |
| **Space Complexity** | `O(V)` | For the `visited` array and the recursion call stack (which can go as deep as `V` in the worst case, e.g., a straight chain of rooms). |

## Edge Cases Considered

- **Single room** (`rooms = [[]]`): Trivially `true`, since room 0 is already visited and `count == n == 1`.
- **Disconnected rooms**: If some room is never reachable via any chain of keys starting from room 0, `count` will be less than `n`, correctly returning `false`.
- **Cycles**: Handled gracefully because of the `visited` check — the DFS won't loop forever.
- **Self-referencing keys** (a room containing a key to itself): Also safely handled since `visited[vertex]` is set before iterating over its keys.

## Summary

This problem reduces to checking **graph connectivity** from a source node — specifically, whether a single DFS traversal starting at node `0` can reach every other node in the graph. The `rooms` array doubles as the adjacency list, so no additional graph-building step is needed. The solution runs in linear time relative to the total number of rooms and keys.
